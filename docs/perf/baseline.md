# Базовая линия и воспроизводимость

Первый локальный ARM64 baseline: 100/300/500/1000 requests/s, по3×180s после60s прогрева.
Новая JVM и topics на каждую конфигурацию; после каждого окна — дренаж и полная сверка UUID.
Контейнеры имеют одинаковые CPU/heap/память лимиты, весь JDBC/Kafka трафик идёт через Toxiproxy.
Две платформенные нити, Hikari10, batch128, poll200ms, tracing выключен.

| rps | HTTP p99 ms median [min;max] | E2e p99 ms median [min;max] |
|---:|---:|---:|
|100|2,81 [2,73;2,89]|233,11 [232,82;234,69]|
|300|2,32 [2,23;3,20]|244,95 [244,48;266,23]|
|500|1,83 [1,67;1,86]|262,12 [260,42;264,05]|
|1000|1,80 [1,66;1,94]|344,51 [343,52;349,20]|

Во всех12 окнах нет ошибок HTTP, dropped iterations, потерь, повторных платежей и очереди
после дренажа. Сырые k6 summaries и measurement samples: `20261009T094122Z-first-baseline-100*`
и `20261009T115214Z-first-baseline-{300,500,1000}*` в `perf-harness/results/`.
Manifest содержит CPU/память Docker VM, effective compose, commit и image IDs.
E2e p99 вычисляется по разности bucket counters за окно, с интерполяцией, а не по накопленной
гистограмме всего процесса. HTTP p99 — k6 Trend. Часы проверяются относительно monotonic clock.

Повторная полная локальная кампания `repeat` запущена на тех же замороженных Docker images.
Параллельно отдельная Linux/x64 CI VM выполняет свою полную первую и повторную базовую
линию, overhead и saturation. Эти архитектуры не усредняются между собой. Итог проверки
воспроизводимости появится только после всех12 окон повторной кампании: медиана каждого
HTTP и e2e p99 должна попасть в min/max первой серии. Изменение порогов или выбросов
задним числом не допускается.

Первый вариант стенда с Toxiproxy quota0,25CPU исключён: прокси достигал квоты раньше
приложений. Новая квота2CPU применяется ко всем принятым данным. Подробности и исходные
файлы — `results/excluded-proxy-quota/`. При следующем старте100rps был валиден, но хост
заснул на300rps: окно180s растянулось почти до5971s. Все300rps окна этой кампании исключены
и измерены заново; корректные три100rps окна сохранены. `results/excluded-host-sleep/`
содержит исходные данные и причину. Harness удерживает awake assertion и отказывает при
sleep/clock discontinuity; исключённые окна не входят в сводки или графики.
